# 手柄模块说明

## 对外接口

业务代码可在 **FreeRTOS 任务上下文**调用以下读取和发送接口。

### 获取解析后的数据

声明位置：`BSP/gamepad/bsp_gamepad.h`

```c
#include "bsp_gamepad.h"

bsp_gamepad_data_t pad = bsp_gamepad_get_data();

if (pad.connected && pad.valid) {
    if ((pad.buttons & BSP_GAMEPAD_A) != 0U) {
        // A 键当前按下
    }
    // pad.lt、pad.rt：左右扳机，范围 0～255
    // pad.lx、pad.ly、pad.rx、pad.ry：四个有符号 16 位摇杆轴
}
```

`connected` 表示 USB 手柄类是否就绪；`valid` 表示最近一包通过了解包函数的基本格式检查。只有 `valid` 为 1 时，才应使用解析后的输入。`buttons` 是按键位掩码，可用 `&` 检查单个按键。多个按键同时按下时，可用 `(pad.buttons & (BSP_GAMEPAD_A | BSP_GAMEPAD_B)) == (BSP_GAMEPAD_A | BSP_GAMEPAD_B)` 判断 A、B 是否都按下。

`motion_h`、`motion_v` 是参考报文格式中的实验性字段，`motion_available` 为 1 仅说明长度足够；目前不能将它们认定为经过校准的陀螺仪或加速度数据。

### 获取原始数据

声明位置：`BSP/gamepad/bsp_gamepad.h`；结构体定义保留在 `BSP/gamepad/gamepad/gamepad.h`。

```c
#include "bsp_gamepad.h"

gamepad_raw_data_t raw;
bsp_gamepad_get_raw_data(&raw);

if (raw.connected && raw.length > 0U) {
    // raw.data[0] 到 raw.data[raw.length - 1] 为最近一包有效字节
}
```

| 字段 | 作用 |
| --- | --- |
| `connected` | USB 手柄类是否就绪；不是最新报文是否有效的保证。 |
| `length` | 最近一包的实际字节数；断开时清零。 |
| `data` | 最近一包原始字节，只有前 `length` 个有效，缓冲区最大 64 字节。 |
| `reports` | 当前连接收到的非空报文数。 |
| `errors` | 当前连接记录的 USB 传输错误数。 |

`bsp_gamepad_get_raw_data()` 调用底层函数，把当前快照复制到调用者的变量；它不是发起 USB 接收的函数。传入 `NULL` 时不进行复制。复制使用临界区，防止 USB Host 任务写入时读到不完整数据。

### 发送原始数据

声明位置：`BSP/gamepad/bsp_gamepad.h`（BSP 对外接口）

```c
#include "bsp_gamepad.h"

uint8_t command[] = {0x00, 0x08, 0x00, 0x80, 0x80, 0x00, 0x00, 0x00};
if (bsp_gamepad_send_data(command, sizeof(command))) {
    // 请求已接受；通过 bsp_gamepad_get_send_status() 查询传输结果。
}
```

发送接口只接受一包尚未完成的请求；未连接、忙碌或参数无效时返回 0，接受请求返回 1。接口会复制数据，USB Host 任务再通过 OUT 端点异步发送。`GAMEPAD_TX_SENT` 只说明 USB 传输完成，不代表设备已执行命令；`GAMEPAD_TX_FAILED` 表示发送失败，`GAMEPAD_TX_DISCONNECTED` 表示 OUT 端点不可用。发生端点 STALL 时当前标记失败，不自动清除端点的暂停状态。上面的 Xbox 兼容震动命令尚未在此手柄验证，停止震动需要另外发送两个强度均为 0 的报文。

## 数据从哪里读取

真正处理 USB 接收的是 ST USB Host 及其任务。当前工程 `USBH_USE_OS=1`，USB Host 初始化时创建内部任务；该任务由 USB 事件驱动，运行 `USBH_Process()`。流程如下：

1. `gamepad_usb.c` 的 `gamepad_process()` 在 **USB Host 任务**中提交中断 IN 接收，使用 `host.buffer` 保存数据。
2. USB 外设和中断处理传输；任务检查到 `USBH_URB_DONE` 后读取本次实际接收长度。
3. 任务调用 `gamepad_store_report()`，将报文复制到 `gamepad.c` 中的 `latest`。
4. 业务任务调用 `bsp_gamepad_get_raw_data()` 取得一份快照；或调用 `bsp_gamepad_get_data()`，由该接口先复制快照，再在本文件内部解包并返回结果。

`gamepad_sof()` 在 SOF 中断中通知 USB Host 任务，**不在中断中解析或打印报文**。手柄 APP 任务只是使用上述接口获取快照和打印，不直接负责 USB 端点接收。

这里只保留最新一包，不是报文队列；业务读取较慢时，中间的状态变化可能被覆盖。`valid` 目前也不包含收包超时判断。

## 文件职责

| 文件 | 作用 |
| --- | --- |
| `BSP/gamepad/gamepad/gamepad_usb.c` | USB Host 自定义类：匹配设备与接口、查找 IN/OUT 端点、申请和释放 pipe、处理接收及异步发送状态。 |
| `BSP/gamepad/gamepad/gamepad_usb.h` | 声明供 USB Host 注册的 `USBH_Gamepad_Class`。 |
| `BSP/gamepad/gamepad/gamepad.c` | 保存最近一包原始报文、连接状态及计数；实现原始快照读取和发送接口。 |
| `BSP/gamepad/gamepad/gamepad.h` | 定义 `gamepad_raw_data_t`，声明原始数据读取接口 `gamepad_get_raw_data()`。 |
| `BSP/gamepad/gamepad/gamepad_internal.h` | 声明 USB 类更新原始数据的内部函数，业务代码无需调用。 |
| `BSP/gamepad/bsp_gamepad.c` | 获取原始快照并按参考格式解包；解包函数仅在本文件内使用。 |
| `BSP/gamepad/bsp_gamepad.h` | 定义解析结果、按键掩码，声明原始数据、解析数据及发送接口。 |
| `APP/app_gamepad/app_gamepad.c` | 手柄应用任务：读取解析结果并通过调试串口打印。 |
| `APP/app_gamepad/app_gamepad.h` | 声明手柄应用任务入口。 |

相关的 CubeMX 生成代码位于 `USB_HOST/App/usb_host.c`：其用户代码区将生成的类注册重定向到 `USBH_Gamepad_Class`。`Core/Src/freertos.c` 创建应用任务并在默认任务中初始化 USB Host。重新生成 CubeMX 后应检查用户代码区和 USB Host 配置。

## 已知设备与验证情况

实机曾读取到 VID/PID `045E:028E`、接口 `FF/5D/01`，以及 32 字节输入报文。解析器参考 Xbox 兼容格式：报文头为 `00`、第二字节至少为十六进制 `14`；第 2～3 字节为按键，第 4～5 字节为扳机，第 6～13 字节为四个小端有符号摇杆轴。具体按键、方向和运动字段仍应逐项实机核对；相同 VID/PID 不能唯一证明设备身份。
